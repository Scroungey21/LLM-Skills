# Animation, audio, editing and rendering

Contents: 1 Animation grammar · 2 Motion budget and cadence · 3 Compositor and renderer contract · 4 Audio (narration, music, SFX, mix) · 5 Edit compiler and transitions · 6 Subtitles · 7 Mapping to the toolkit

Sources: Report §12-§14, §13.5, Blueprints 10, 12, 13, §25.5. Exact target animation/audio/edit grammar is **unmeasured** (Report §12.1, §13.1); everything numeric here is a labelled default.

## 1. Animation grammar (Report §12.2)

The minimum capability set that suffices for a high-quality first implementation - all expressed as **timed properties, not baked video clips**: layer translation · scale · rotation · opacity/reveal · path-following · character joint interpolation between vector poses · prop attachment/handoff · camera pan/zoom/reframe · simple parallax (background/midground/foreground) · mask/wipe/reveal · text entrance/highlight/underline · diagram edge/node activation · brief emphasis shake/bounce · pose swap with optional 2-6 frame eased interpolation.
Do not build expensive frame-by-frame character animation prematurely (§12.1). In the schema these are `animationEvent.property` values `POSITION, SCALE, ROTATION, OPACITY, POSE, EMOTION, CAMERA_CENTER, CAMERA_ZOOM, PATH_PROGRESS, MASK_REVEAL, TEXT_REVEAL, SHAKE, DRAW_PROGRESS` with `interpolation` `STEP, LINEAR, EASE_IN, EASE_OUT, EASE_IN_OUT, SPRING, CUSTOM_BEZIER`; sub-parts via `target_component`; world-space behaviour via `constraints` (`LOCK_POSITION/LOCK_X/LOCK_Y/FOLLOW/LOOK_AT/MAINTAIN_DISTANCE/ATTACH/DETACH` in `WORLD/LOCATION/SCREEN/PARENT` space). See [storyboard-schema §5](storyboard-schema.md).
Event contract in the report (§12.3): `event_id, target_id, property, from, to, start, end, interpolation, trigger: narration_token:..., must_complete_before:[...]`. The shipped schema has no `trigger`/`must_complete_before` (extra keys are illegal) - keep the narration binding in a sidecar `alignment_bindings.json` `{event_id: {token_index|word, window_sec}}` and check ordering there (PROPOSED).
**All event times must finally align to the final narration audio**, not text-length guesses (§12.3, §5 of [pipeline](pipeline-and-agent-roles.md)).

## 2. Motion budget and cadence

- **Motion budget** (§12.4): reject motion that does not (a) clarify action, (b) direct attention, (c) reveal a causal sequence, (d) preserve spatial continuity, (e) punctuate a rhetorical beat, or (f) maintain energy during a long static explanation. This prevents "every layer constantly floats".
- **Calibration envelopes, not quotas** (§12.5): after measurement compute `major_visual_state_change_interval`, `hard_cut_interval`, `pose_change_rate`, `camera_motion_rate`, `overlay_event_rate`, `static_hold_p90`; a shot may exceed the median when continuity/comprehension needs it. Until measured: use a **local default** stated by the owner (candidate: the HES rule "visual change at least every 3.5 s", plus Handoff "a visual event every 1-3 narration sentences") and log it in `style_profile.local_default`, never in the measured block.
- **Objective render checks** that catch dead video (Material Trials' thresholds, borrowed as a starting point, not stickman-validated): no run >1.0 s where nothing in the picture changes except holds you declare, mean luma > 4 (no black frames), no out-of-bounds text ([qa-gates §9](../../../references/qa-gates.md) rows "No freezes"/"No black frames"; visual-change cadence per channel in [qa-gates §7](../../../references/qa-gates.md): news 6-12 s, HES 3-5 s; [rendering §9](../../../references/rendering.md)).
- HES-derived physics cleanliness for diagrams (streams need a source, angles never wrap, nothing stops dead in view) is relevant for any animated mechanism: [everyday-systems visual-system §4](../../everyday-systems-explainer/references/visual-system.md).

## 3. Compositor and renderer contract (Blueprint 10)

Input: one storyboard shot + resolved assets + style profile + timing/alignment. Algorithm: build the scene graph from ordered `layers` -> apply entity/component transforms and rig pose -> resolve attachments to named anchors -> execute animation curves at frame time -> apply the **camera transform separately from the world transform** -> render deterministic overlays/text **last** -> encode a lossless/intermediate segment. Output: segment video + optional debug overlay/contact frame + render manifest (Report §25.5: shot ids, storyboard hash, asset hashes, audio hash, renderer/ffmpeg versions, style-profile hash, output + hash).
Quality: no unresolved layer; every required entity inside composition bounds (respect `safe_margins_pct`); text readable; **frame hashes deterministic for the same inputs**; deterministic render failure = fix input/renderer, no random retry; re-render only dirty segments (`--dirty-only`). The renderer refuses schema-invalid storyboards.
Segment-based rendering means a changed shot re-renders only its own interval plus required handles (§14.2).

## 4. Audio

- **Narration order** (Report §13.2, Blueprint 12): `approved script -> pronunciation pass -> TTS -> forced alignment -> storyboard retime -> mix`. Retain the existing TTS layer; add style at the **prosody-instruction level** rather than switching vendors: declarative baseline; slight pause before an important reversal; stress on the noun that resolves a setup; shorter pause after a rhetorical question than after a section boundary; do not read citations/URLs aloud unless editorially intended; pronounce species and researcher names via a lexicon. Voice engine rules, cadence gate (165-240 WPM native-take rule is HES's), seed retry, GPU rule: [voice-tts](../../../references/voice-tts.md). One voice per video. Never time-stretch to pass a gate.
- **Music** (§13.3): small licensed/local instrumental library with semantic tags rather than generative music by default. Track record: `track_id, license, bpm, energy (0-1), mood[], loop_points[], stems[]`. Storyboard sections request an `energy_delta`, not arbitrary track changes; prefer one coherent bed with controlled rises/drops. Licence/credit discipline: [audio-captions-music §5](../../../references/audio-captions-music.md) (exact credit text in the description; HES's CC BY library is that channel's - decide your own).
- **SFX** (§13.4): metadata-driven triggers only - object impact/placement -> impact token; arrow/node activation -> subtle reveal token; whoosh only for a meaningful fast transition; animal action -> species-appropriate sound only if factually non-misleading and not distracting; danger event -> restrained accent; **no generic SFX on every cut**. Every SFX has a provenance/licence entry ([audio-captions-music §6](../../../references/audio-captions-music.md)). Use `sync_target_event_id` so a retime moves SFX with its animation.
- **Mix gate defaults** (§13.5; engineering defaults, *not* target measurements): no clipped samples; final true peak <= -1 dBTP; narration intelligible under all music/SFX; music ducking typically 12-18 dB relative to standalone musical emphasis, tuned by ear/loudness analysis; abrupt bed changes need storyboard justification; no unresolved pronunciation warnings for names central to the video. The toolkit's measured house chain (-16 LUFS integrated, -1.5 dBTP, sidechain duck, octave-band gate) is in [audio-captions-music §4](../../../references/audio-captions-music.md) and [rendering §5](../../../references/rendering.md) - reuse it rather than inventing a second one.
- **Audio gate** (§27.7): narration matches approved script semantically; no missing/repeated lines; pronunciation exceptions reviewed; alignment confidence acceptable; no clipping; narration intelligible under music/SFX; clean fades/endpoints. A tool session cannot listen - report human listening as pending.

## 5. Edit compiler and transitions (Report §14)

The compiler takes forced-aligned narration tokens, the shot list, visual-state events, music/SFX events, transition rules and subtitles; emits `edit_plan.json` then deterministic ffmpeg/renderer commands. Three units: scenario (persistent world), shot (continuous camera interval), visual state (any meaningful change inside a shot) - a sentence can hold several states without a cut.
Default transition hierarchy (§14.3, PROPOSED): 1) same scenario + same camera -> no transition, animate state; 2) same scenario + new camera -> direct cut or short transform; 3) scenario -> explanatory insert -> cut/reveal, then return to stored state; 4) major time/location jump -> direct cut with optional location label; 5) montage -> common template, regular internal rhythm; 6) section boundary -> stronger punctuation allowed. **No library of decorative transitions**: consistency and semantic causality beat flourish. Camera never goes out-and-back on the same focus (HES owner rule; adopt as a channel decision).
Edit compiler checks (Blueprint 13): continuous timeline (no gaps/overlaps), segment handles, SFX scheduled from storyboard triggers, music by energy plan, ducking under voice, subtitles from final alignment, mix/encode with ffmpeg.

## 6. Subtitles (§14.4)

Generate from **final aligned narration**, not the pre-TTS script; store word timestamps and line breaks separately; render burned-in captions **only if the chosen format profile calls for them** (the report does not assume the target uses full burned-in captions - unobserved). If the channel adopts captions, use the toolkit's caption pipeline and respect the owner's banned look (no Arial/Arial Black, no coloured spoken word): [audio-captions-music §2](../../../references/audio-captions-music.md). Captions must not cover mechanisms/labels (HES validator "caption safety").

## 7. Mapping to the toolkit (details: [toolkit-mapping](toolkit-mapping.md))

SVG rigs and diagrams are natural React/SVG components in the bundled Remotion project; render a **JPEG frame sequence** and mux with system ffmpeg (never `renderMedia`, Remotion's bundled ffmpeg crashes on this host) - [rendering §2](../../../references/rendering.md). Word timing: faster-whisper/WhisperX as the HES pipeline does ([voice-tts §4](../../../references/voice-tts.md)). Final encode / loudness commands: [rendering §5](../../../references/rendering.md).
